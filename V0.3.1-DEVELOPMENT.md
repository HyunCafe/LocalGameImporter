# Local Game Importer v0.3.1 - build and safety checklist

This development patch updates the source. **Git does not update an installed Playnite DLL.**
Version v0.3.0 on GitHub stays unchanged until v0.3.1 is separately built, tested and published.

## Setup

This project targets .NET Framework 4.6.2 and the official PlayniteSDK 6.18.0 package.
The optional `LocalGameImporter.csproj` pins both official NuGet package versions.
Dependencies are pulled during `dotnet restore` from your configured NuGet sources; examine
your NuGet source configuration before restoring. No third-party code is executed by scanning.

```bash
dotnet nuget list source
dotnet restore ./LocalGameImporter.csproj --source https://api.nuget.org/v3/index.json
pwsh -NoLogo -NoProfile -File ./Tools/Verify-Dependencies.ps1
dotnet build ./LocalGameImporter.csproj -c Release --no-restore
pwsh -NoLogo -NoProfile -File ./Tests/Run-Tests.ps1
```

Built DLL: `bin/Release/net462/LocalGameImporter.dll`.
If `dotnet build` rejects a WPF reference or other API member, stop. Do not distribute a DLL
that failed to compile. Use `Build.ps1` with the original pinned extracted SDK/framework
references as a fallback; see `BUILD.md`.

## UI verification in Playnite

- A single click on an Add checkbox toggles the game without first selecting the row.
- Ctrl/Shift-clicking game titles still selects a range for the bulk actions.
- Newly imported `ADDED` rows disappear from the review list immediately; check the `Show imported / existing games` option to inspect them read-only. Counts and Select imports for metadata still include them.
- A new scan keeps path-verified `EXISTING` games out of the review list by default. Same-title `NAME MATCH` rows stay visible for explicit duplicate review.
- Unresolved `INCOMPLETE` games (including intentionally skipped ones) remain unchanged until manually reviewed.

## Local package and test

After a successful compile, run `Tools/Package-Release.ps1` to create a private local `.pext`.
It verifies the DLL assembly version, files and SHA-256, and does not push anything.

```bash
pwsh -NoLogo -NoProfile -File ./Tools/Package-Release.ps1
```

To retain a prior local build, use `pwsh -NoLogo -NoProfile -File ./Tools/Package-Release.ps1 -OutputName LocalGameImporter-0.3.1-r2.pext` for a separate local iteration. The package version stays 0.3.1; only the archive name changes. Do not overwrite the earlier tested package.

`../Releases/LocalGameImporter/LocalGameImporter-0.3.1.pext` is a local candidate only. Install it in Playnite
and test multi-selection, bulk preview, blocking errors, partial import, existing games,
scan folders, and metadata. Test v0.3.1 before tagging or uploading a public release.

The old `BUILD-INPUTS.json` describes the **published v0.3.0** reproducibility snapshot,
not the new 0.3.1 build. Do not re-label that old SHA-256 value as the new DLL hash.
Package v0.3.1 includes the actual new DLL and fresh checksums; it does not include the
stale v0.3.0 build-input record.
